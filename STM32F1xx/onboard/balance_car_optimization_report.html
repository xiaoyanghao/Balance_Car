STM32 平衡小车控制优化分析报告

项目路径: C:\E\33-Balance\STM32F1xx\onboard  |  MCU: STM32F105  |  IMU: MPU6050 (DMP)  |  电机驱动: TB6612

总体评估

本项目是一套基于 STM32F105 + MPU6050 + TB6612 的两轮自平衡小车控制系统。代码结构分为驱动层(BSP)、外设层(Periph)、传感器层(Sensor)、控制层(Control)和接口层(Interface)。整体架构合理，具备安全保护机制(IMU超时、倾倒保护、数值校验)。

但经过逐层代码审查，发现 12 个可优化点，涉及传感器数据链路冗余、控制算法精度、任务调度效率、电机死区补偿等多个方面。以下按严重程度分级列出。

核心发现: 项目中存在大量从飞控系统移植过来的传感器处理和 AHRS 融合代码（imu.c、txg_ahrs_fusion.c），但实际运行时这些路径全部被旁路，系统直接使用 MPU6050 DMP 输出的四元数和陀螺仪数据。这导致：

  • 约 1500 行代码处于死代码状态，增加维护负担
  • 软件 I2C + DMP FIFO 轮询的通信方式效率较低
  • DMP 输出的陀螺仪数据未经额外滤波，直接进入 PID 控制

2 底层驱动层 (BSP / Periph)

高 编码器输入捕获滤波器为零 (ICFilter=0) bsp_timer_drv.c L277,281

问题描述: TIM3/TIM5 编码器模式中，输入捕获滤波器设置为 0，对编码器信号不做任何硬件滤波。在电机高速运转时，编码器信号容易受到电机 PWM 干扰产生毛刺，导致计数值跳动。

// bsp_timer_drv.c L277,281 — 当前设置
sConfig.IC1Filter = 0;
sConfig.IC2Filter = 0;

// 编码器线: 374 脉冲/圈(正交×4 = 1496计数/圈)
// 350RPM → 5.83 rev/s → ~8734 counts/s
// 5ms 采样 → ~44 counts/次, 噪声毛刺会显著影响速度测量
优化建议

将输入捕获滤波器设为 4~8（在 72MHz 时钟下约 0.7~1.4μs 的滤波窗口），可有效抑制电机 PWM 开关噪声引起的编码器毛刺：

// 推荐修改
sConfig.IC1Filter = 6;  // 约 1μs 滤波窗口
sConfig.IC2Filter = 6;
高 软件 I2C 通信效率低，DMP 轮询存在 50% 空转 periph_mpu60x0.c / bsp_i2c_drv.c L285-293 / main.c L58

问题描述: MPU6050 使用软件模拟 I2C（GPIO 位操作），每次读写都是阻塞式的。DMP 采样率设为 100Hz（mpu_dmp_init 中 mpu_set_sample_rate(100) 和 dmp_set_fifo_rate(100)），但主循环以 200Hz（5ms）轮询 mpu_dmp_get_data()。由于 DMP FIFO 每 10ms 才更新一次数据，50% 的 dmp_read_fifo 调用会因 FIFO 无新数据而提前返回，但这些调用仍会执行完整的 I2C 读写时序，浪费 CPU 时间。

// main.c L58 — DMP 轮询任务 5ms 一次
{0, 5, 0, mpu_dmp_get_data},

// txg_ahrs_fusion.c L2074 — DMP 采样率 100Hz = 10ms
res = mpu_set_sample_rate(100);
res = dmp_set_fifo_rate(100);

// txg_ahrs_fusion.c L2118 — 若 FIFO 无数据则直接返回
if(dmp_read_fifo(gyro, accel, quat, &sensor_timestamp, &sensors, &more))
    return;
优化建议 (二选一)

方案A: 将 DMP 轮询周期从 5ms 改为 10ms，与 DMP 100Hz 输出率对齐，消除空转：

// main.c — 将 5 改为 10
{0, 10, 0, mpu_dmp_get_data},

方案B: 使用 MPU6050 的 DATA 中断引脚触发读取，避免轮询浪费。MPU6050 已配置了中断（periph_mpu60x0.c L144: reg 55 = 0x10, reg 56 = 0x01），但未连接到 MCU 的外部中断引脚。若硬件上中断引脚已连接，可配置 EXTI 触发读取。

方案C (最优): 改用硬件 I2C + DMA 读取 MPU6050 寄存器，将读取时间从数毫秒降至数十微秒。

中 电机死区补偿存在零点穿越跳变 control.c L128

问题描述: control_apply_motor() 中，死区补偿值 (180) 是在电机已转动后直接叠加到 PWM 幅值上。当 PWM 从 0 跨越到非零时，输出会从 0 突跳到 180，造成电机扭矩突变，产生可闻的"咔哒"声和速度抖动。

// control.c L128 — 死区补偿直接叠加
magnitude += (float)dead_zone;
magnitude = clamp_float(magnitude, 0.0f, (float)BSP_TIM1_PWM_PERIOD);
优化建议

使用平滑过渡的死区补偿：当 PWM 幅值在死区附近时线性插值，避免突跳：

// 改进方案: 分段平滑死区补偿
static float apply_dead_zone_compensation(float mag, uint16_t dead_zone)
{
    const float transition_width = (float)dead_zone * 2.0f;
    if (mag <= 0.0f) return 0.0f;
    if (mag < transition_width) {
        // 在 0~transition_width 范围内从 0 线性过渡到 dead_zone
        return mag * (dead_zone / transition_width);
    }
    return mag + dead_zone;
}

3 传感器层 (IMU / AHRS)

高 DMP 陀螺仪数据未滤波直接用于 PID 微分项 control.c L205

问题描述: 控制器的平衡 PD 环使用了 pitch_gyro 作为微分项。该值来自 DMP FIFO 的原始陀螺仪数据（已转换为 deg/s），但 MPU6050 的内部 LPF 寄存器 (reg 26) 设为 0x00，即 256Hz 带宽——这意味着几乎没有低通滤波。原始陀螺仪数据中的高频噪声会被 BALANCE_KD=7.53 放大，导致 PWM 输出抖动。

// periph_mpu60x0.c L141 — MPU 内部 LPF 设为 0 (256Hz带宽)
mpu60x0ReliablySetReg(26, 0x00);

// control.c L205 — 直接使用 DMP 原始陀螺仪
_control.pitch_gyro = (float)imu_get_gyro(IMU_INSTANCE_MPU, 1);

// control.c L75 — 微分项乘以 Kd=7.53
return _control.balance_kp * (pitch - BALANCE_ANGLE)
     + _control.balance_kd * pitch_rate;
优化建议

方案1 (最简单): 将 MPU6050 内部 LPF 寄存器设为 3 或 4（对应 42Hz 或 20Hz 带宽），在硬件层面滤除高频噪声：

// 在 mpu_dmp_init 中追加配置
mpu60x0ReliablySetReg(26, 0x03);  // 42Hz LPF

方案2 (更灵活): 在控制层对 pitch_gyro 加一阶或二阶低通滤波器，可调截止频率。项目已有现成的 Butterworth 滤波器实现:

// 在 control.c 中添加
static struct SecondOrderLowPass_t _gyro_lpf;
static bool _gyro_lpf_inited = false;

static float filter_pitch_gyro(float raw)
{
    if (!_gyro_lpf_inited) {
        init_second_order_low_pass(&_gyro_lpf, 40.0, 200, 0.707, raw);
        _gyro_lpf_inited = true;
    }
    return (float)update_second_order_low_pass(&_gyro_lpf, (double)raw);
}
中 大量传感器处理代码为死代码，IMU 模块初始化空转 imu.c L71-90

问题描述: imu.c 中的 imu_init() 函数几乎全部被注释，只调用 mpu60x0_init() 而 mpu60x0_init() 又未启用传感器（config 被注释，返回 0）。实际传感器初始化完全依赖 eMPL 库的 mpu_dmp_init()。imu_get_gyro/acc 等函数全部绕过本地滤波管线，直接调用 get_dmp_gyro/accel。imu.c 中约 400 行代码（校准、滤波、坐标旋转）处于未使用状态。

优化建议

有两种策略，取决于项目目标:

  • 策略A (推荐 — 精简): 删除或归档 imu.c 中未使用的代码路径，只保留 DMP 接口封装。减少编译体积和维护成本。
  • 策略B (增强): 恢复 imu.c 中的本地校准和滤波管线，绕过 DMP 直接读取原始寄存器数据，应用自定义校准和 Butterworth 滤波。这可以提升传感器数据质量，但需要较多开发工作。
中 DCM AHRS 融合算法被完全旁路 txg_ahrs_fusion.c L156, L1782-1798

问题描述: txg_ahrs_fusion.c 实现了一套完整的 ArduPilot 风格 DCM 姿态估计算法（约 1900 行），包括陀螺仪积分、加速度计漂移校正、偏航修正等。但 ahrs_update_fusion() 在 main.c 中被注释掉，get_roll_deg/get_pitch_deg/get_yaw_deg 直接返回 DMP 计算的欧拉角。

// main.c L59 — AHRS 融合被注释
// {0, 5, 0, ahrs_update_fusion},

// txg_ahrs_fusion.c L1784 — 直接返回 DMP 数据
double get_roll_deg(void) {
    return get_dmp_ahrs(1);  // 直接用 DMP 四元数
}
优化建议

当前 DMP 的姿态估计对于平衡小车已经够用。但 DMP 的偏航角（yaw）存在长时间漂移问题。如果需要精确偏航控制，建议:

  • 保留 DMP 用于 pitch/roll 估计（DMP 的 6 轴 quaternion 在 pitch/roll 上精度良好）
  • 对 yaw 通道增加简单的互补滤波器融合陀螺仪积分和 DMP yaw 输出，纠正漂移
  • 或恢复 DCM 算法，但需要清理大量 GPS/RTK 相关的死代码（约 600 行被注释的代码块）

4 控制算法层 (PID)

高 速度积分项缺少 dt 时间因子，抗干扰能力弱 control.c L88

问题描述: 速度环的积分累加 _speed_integral += speed_error 没有乘以时间增量 dt。当前隐式假设控制周期固定为 5ms（200Hz），但实际由于协作式调度器，如果高优先级任务（如 I2C 通信）阻塞，控制周期会波动。缺少 dt 会导致积分速率不稳定，且在周期变化时积分增益等效变化。

// control.c L88 — 当前: 无 dt
_speed_integral += speed_error;  // 隐式假设 5ms 周期

// 对比: BALANCE_KP 的注释表明使用了 Z-N 法
// BALANCE_KP = 120 * 0.6 = 72 (Ziegler-Nichols PD)
// VEL_KI = 140/200 = 0.7, 此处 200 即为假设的采样率
优化建议

引入实际 dt（通过 HAL_GetTick 计算），使积分项与时间相关而非与调用次数相关:

// 在 Control_Updte 开头计算 dt
static uint32_t last_tick = 0;
float dt = (float)(HAL_GetTick() - last_tick) * 0.001f;
last_tick = HAL_GetTick();
if (dt <= 0.0f || dt > 0.05f) dt = 0.005f;  // 合理范围保护

// 积分累加改为
_speed_integral += speed_error * dt;

// 同时调整 VEL_KI 定义, 从 140/200 改为以秒为单位
// 原 VEL_KI=0.7 对应 5ms 周期, 等效 KI_sec = 0.7 / 0.005 = 140
#define VEL_KI  140.0f  // 单位: 1/s
中 转向环 turn_kd 参数已接收但未使用 control.c L97-101, L162

问题描述: 控制器结构体定义了 turn_kd 参数，网络接口 Control_Set_PramA() 也接收该参数，但 control_turn() 函数只用 P 控制，turn_kd 始终为 0 且未参与计算。纯 P 控制的转向环在目标偏航速率突变时容易产生超调。

// control.c L97 — 转向环只有 P
static float control_turn(float target_yaw_rate)
{
    float yaw_rate_error = _control.yaw_gyro - target_yaw_rate;
    return _control.turn_kp * yaw_rate_error;  // 无 D 项
}

// control.c L162 — turn_kd 初始化为 0
_control.turn_kd = 0.0f;
优化建议

加入转向微分项，阻尼偏航速率振荡:

// 增加转向速率的微分
static float prev_yaw_rate_error = 0.0f;

static float control_turn(float target_yaw_rate)
{
    float yaw_rate_error = _control.yaw_gyro - target_yaw_rate;
    float derivative = (yaw_rate_error - prev_yaw_rate_error) / 0.005f;
    prev_yaw_rate_error = yaw_rate_error;
    return _control.turn_kp * yaw_rate_error
         + _control.turn_kd * derivative;
}
中 速度滤波器使用简单一阶 IIR，滤波效果有限 control.c L85

问题描述: 速度测量使用一阶 IIR 滤波 alpha=0.23。在 200Hz 采样率下，截止频率约 7.3Hz。这个滤波器的滚降率为 -20dB/dec，对电机高频噪声抑制不足。且 alpha 值固定，无法在运行时调整。

优化建议

项目已有现成的二阶 Butterworth 滤波器实现（txg_low_pass_filter.c），可直接使用:

static struct SecondOrderLowPass_t _speed_lpf;
static bool _speed_lpf_inited = false;

// 在 control_velocity() 中
float measured_speed = (_control.lencode_spd + _control.rencode_spd) * 0.5f;
if (!_speed_lpf_inited) {
    init_second_order_low_pass(&_speed_lpf, 10.0, 200, 0.707, measured_speed);
    _speed_lpf_inited = true;
}
_control.encode_spd = (float)update_second_order_low_pass(
    &_speed_lpf, (double)measured_speed);

二阶 Butterworth (Q=0.707) 提供 -40dB/dec 滚降，在相同截止频率下噪声抑制更好。

低 平衡角度偏置为硬编码常量 control.c L8

问题描述: BALANCE_ANGLE = 0.25° 是小车的机械平衡点，硬编码在源码中。不同小车的重心位置不同，平衡角度也不同，每次修改需要重新编译。

优化建议

将平衡角度加入 NET_RA 结构体，通过上位机在线调整，或存储到 EEPROM (项目已有 AT24C512B 驱动):

// 在 struct CONTROL 中添加
float balance_angle;  // 可调平衡偏置

// control_balance 中使用
return _control.balance_kp * (pitch - _control.balance_angle)
     + _control.balance_kd * pitch_rate;

5 任务调度层

中 协作式调度器无优先级，I2C 阻塞影响控制实时性 main.c L54-65, L127-142

问题描述: sys_task_run() 是一个简单的轮询式调度器，按数组顺序检查并执行就绪任务。没有优先级抢占机制。如果 mpu_dmp_get_data() 因 I2C 通信阻塞（软件 I2C 可能需要 2-5ms），后续的 Control_Spd_Updte 和 Control_Updte 会被延迟执行，导致控制周期抖动。

// main.c L54-65 — 任务列表（按数组顺序执行）
static struct TaskStruct systask[SYS_TASK_NUM] = {
  {0, 500,  0, Bsp_Gpio_LED_Toggle},
  {0, 5,    0, mpu_dmp_get_data},      // I2C阻塞 ~2-5ms
  {0, 5,    0, Control_Spd_Updte},     // 可能被延迟
  {0, 5,    0, Control_Updte},          // 可能被延迟
  {0, 20,   0, Net_Link_Decode},
  {0, 2,    0, Net_Link_Out},
  {0, 1000, 0, Rcc_Cpu_Loadcal},
};
优化建议

短期方案: 调整任务顺序，将控制任务放在 DMP 读取之后、其他低优先级任务之前，确保控制任务优先执行:

static struct TaskStruct systask[SYS_TASK_NUM] = {
  {0, 5,    0, Control_Spd_Updte},     // 优先: 编码器读取
  {0, 10,   0, mpu_dmp_get_data},      // 其次: DMP (改为10ms)
  {0, 5,    0, Control_Updte},          // 优先: 控制计算
  {0, 20,   0, Net_Link_Decode},       // 低优先级
  {0, 10,   0, Net_Link_Out},          // 低优先级
  {0, 500,  0, Bsp_Gpio_LED_Toggle},
  {0, 1000, 0, Rcc_Cpu_Loadcal},
};

长期方案: 将控制循环移入定时器中断（如 TIM2），保证严格的固定周期执行；DMP 数据读取放在主循环中以非阻塞方式完成。

6 通信层

低 Net_Link_Out 任务频率过高且遥测帧被禁用 main.c / net_link.c L63, L465-487

问题描述: Net_Link_Out 注册为 2ms 任务（最高频率），但内部使用计数器每 5 次才发送一次（10ms 有效周期），其余 4 次空转。同时 TA 帧（传感器遥测数据）的发送被注释掉，只发送 TB 帧（控制参数），无法通过上位机观察传感器原始数据。

优化建议
  • 将 Net_Link_Out 任务周期从 2ms 改为 10ms，与实际发送频率对齐
  • 恢复 TA 帧发送，便于上位机实时调试传感器数据
  • 可考虑将 TA/TB 帧交替发送，在不增加带宽的情况下同时获得传感器和控制数据
