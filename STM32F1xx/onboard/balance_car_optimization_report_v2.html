2 底层驱动层 — I2C / 延时 / 定时器 / 电机

BUG NEW Bsp_Delay_Us 除数错误 — 所有延时实际只有预期的一半 bsp_delay_drv.c L82

问题描述: Bsp_Delay_Us 使用 SystemCoreClock/6000000 作为除数，但文件头注释明确写出的公式是 SystemCoreClock/3000000。SysCtlDelay 每次循环消耗 3 个时钟周期，因此正确除数应该是 3000000（3 cycles/iteration → 1μs = SystemCoreClock/3 cycles = SystemCoreClock/3000000 iterations）。

// bsp_delay_drv.c L36-43 — 注释中的正确公式
/*  SystemCoreClock=120000000
  us级延时,延时n微秒
  SysCtlDelay(n*(SystemCoreClock/3000000));     ← 正确公式
*/

// bsp_delay_drv.c L80-83 — 实际代码使用了错误除数
void Bsp_Delay_Us(unsigned long ulCount)
{
  // 错误: 使用了 /6000000, 实际延时 = 预期的 50%
  SysCtlDelay(ulCount * (SystemCoreClock/6000000));
  // 正确应为:
  // SysCtlDelay(ulCount * (SystemCoreClock/3000000));
}

在 72MHz 主频下：当前代码 SysCtlDelay(12) → 12×3=36 cycles → 36/72MHz = 0.5μs，而非预期的 1μs。这意味着所有 I2C 延时（i2c_delay_us(4) 实际只有 2μs）和 i2c_delay_us(2) 实际只有 1μs，导致 I2C 总线实际运行在约 250kHz 而非预期的 100-125kHz。

影响

虽然短线上 I2C 可能仍能工作，但：① 违反 MPU6050 的 I2C 时序规格（min SCL high/low 0.6μs @400kHz Fast Mode，当前接近极限）；② 长线或高干扰环境下可靠性下降；③ Bsp_Delay_Ms 和 Bsp_Delay_S 同样减半。

修复
void Bsp_Delay_Us(unsigned long ulCount)
{
  SysCtlDelay(ulCount * (SystemCoreClock / 3000000));
}
void Bsp_Delay_Ms(unsigned long ulCount)
{
  SysCtlDelay(ulCount * (SystemCoreClock / 3000));
}
void Bsp_Delay_S(unsigned long ulCount)
{
  SysCtlDelay(ulCount * (SystemCoreClock / 3));
}

注意: 修复后 I2C 速度会减半，每次 DMP 读取时间会增加约 1-2ms。需同步评估是否需要改用硬件 I2C。

高 NEW 软件 I2C 每次字节传输都调用 HAL_GPIO_Init 切换 SDA 方向 bsp_i2c_drv.c L80-109, L212, L239

问题描述: 在 bsp_i2c_send_byte 和 bsp_i2c_read_byte 中，切换 SDA 引脚方向是通过调用 HAL_GPIO_Init 完成的。这个 HAL 函数内部会：检查参数 → 修改 CRL/CRH 寄存器 → 清除配置位 → 设置新模式，开销约 20-50 个时钟周期。而每次 I2C 读字节只需切换一次方向，但在整个 DMP FIFO 读取过程中（28+2 字节），需要调用 bsp_i2c_sda_in 和 bsp_i2c_sda_out 各约 30 次。

// bsp_i2c_drv.c L80-91 — 每次切换方向都完整初始化 GPIO
static void bsp_i2c_sda_out(struct bsp_ioi2c_t *ioi2c)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};        // 栈分配+清零
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;   // 填充结构体
  GPIO_InitStruct.Pull = GPIO_PULLUP;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
  GPIO_InitStruct.Pin = ioi2c->sda_gpio_pin;
  HAL_GPIO_Init(ioi2c->sda_gpio_port, &GPIO_InitStruct); // HAL开销大
}

// bsp_i2c_send_byte: 每发送1字节调用1次 sda_out
// bsp_i2c_read_byte: 每读取1字节调用1次 sda_in
// 一次 DMP FIFO 读取 ≈ 30 字节 → 30 次 HAL_GPIO_Init 调用

实测估算：一次完整的 dmp_read_fifo 需要约 2 次 I2C 读取（fifo_count: 2 字节 + fifo_data: 28 字节 = 30 字节），加上 start/stop/ack 开销，总计约 2-5ms 阻塞时间。在 200Hz 控制周期（5ms）中占比 40-100%。

优化方案（按投入产出比排序）

方案A（最小改动）: 用直接寄存器操作替换 HAL_GPIO_Init，将方向切换从 ~50 cycles 降至 ~5 cycles:

static inline void bsp_i2c_sda_out(struct bsp_ioi2c_t *ioi2c)
{
  // 直接操作 CRH/CRL 寄存器，跳过 HAL 开销
  if (ioi2c->sda_gpio_pin < GPIO_PIN_8) {
    ioi2c->sda_gpio_port->CRL &= ~(0xF << (ioi2c->sda_gpio_pin * 4));
    ioi2c->sda_gpio_port->CRL |= (0x1 << (ioi2c->sda_gpio_pin * 4)); // Output PP 10MHz
  } else {
    uint8_t shift = (ioi2c->sda_gpio_pin - 8) * 4;
    ioi2c->sda_gpio_port->CRH &= ~(0xF << shift);
    ioi2c->sda_gpio_port->CRH |= (0x1 << shift);
  }
}
// sda_in 类似，Mode=0x4 (Floating Input) 或 0x8 (Pull-Up Input)

方案B（最优）: 改用 STM32 硬件 I2C 外设 + DMA，将读取时间从 2-5ms 降至 ~50μs，彻底消除阻塞。MPU6050 SCL(PB6 或 PB10)、SDA(PB7 或 PB11) 需要硬件接在 I2C1/I2C2 上。

方案C: 使用 MPU6050 DATA 中断引脚（已配置 reg 55=0x10, reg 56=0x01）触发 EXTI 中断读取，避免轮询空转。需硬件确认 INT 引脚已连接到 MCU。

高 编码器输入捕获滤波器为零 (ICFilter=0) bsp_timer_drv.c L277,281

问题描述: TIM3/TIM5 编码器模式中 IC1Filter = 0 和 IC2Filter = 0，对编码器信号不做任何硬件滤波。电机 PWM 开关噪声（10kHz）会直接耦合到编码器输入，造成计数跳变。

修复

sConfig.IC2Filter = 6;
高 DMP 100Hz 输出但以 200Hz 轮询 — 50% I2C 空转 main.c / txg_ahrs_fusion.c L58 / L2074

问题描述: mpu_set_sample_rate(100) 和 dmp_set_fifo_rate(100) 将 DMP 设为 100Hz（10ms 更新一次），但主循环以 5ms（200Hz）轮询 mpu_dmp_get_data。dmp_read_fifo 内部先读 fifo_count 寄存器，发现 FIFO 无新数据就返回 -1，但这仍需一次完整 I2C 读操作（2 字节 + start/stop/ack）。

修复
// main.c — 将 DMP 轮询从 5ms 改为 10ms
{0, 10, 0, mpu_dmp_get_data},
中 电机死区补偿零点穿越跳变 control.c L128

问题描述: control_apply_motor 在 PWM 非零时直接叠加死区值 180。当 PWM 从 0 变为非零时，输出从 0 突跳到 180，造成电机扭矩突变和"咔哒"声。

修复 — 分段平滑过渡
static float apply_dead_zone(float mag, uint16_t dead_zone)
{
  const float trans = (float)dead_zone * 2.0f;
  if (mag <= 0.0f) return 0.0f;
  if (mag < trans) return mag * (dead_zone / trans); // 线性过渡
  return mag + dead_zone;
}
中 NEW 电机换向无死区时间 — H桥瞬间短路风险 periph_serial_motor.c / control.c L118-126

问题描述: control_apply_motor 在切换方向时直接调用 Periph_Motor_Set_DF 或 Periph_Motor_Set_DB，中间不经过 Periph_Motor_Set_ST（短路制动/滑行）。TB6612 虽有内置死区时间（~0.3μs），但在高速 PWM 下快速换向仍可能产生电流尖峰。

修复 — 换向前先置 ST
static uint8_t last_dir[2] = {MOTOR_DIR_STOP, MOTOR_DIR_STOP};

if (signed_pwm == 0.0f) {
  /* ...stop... */
} else {
  uint8_t new_dir = (signed_pwm < 0.0f) ? 0 : 1;
  if (new_dir != last_dir[motor_id]) {
    // 方向改变: 先置 ST 再置新方向
    Periph_Motor_Set_ST(motor_id);
    // 可选: 短延时或在此周期输出0, 下周期再输出
  }
  if (signed_pwm < 0.0f) Periph_Motor_Set_DF(motor_id);
  else Periph_Motor_Set_DB(motor_id);
  last_dir[motor_id] = new_dir;
}

3 传感器层 — IMU / AHRS / DMP

高 DMP 陀螺仪 MPU LPF 设为 0 (256Hz) — 高频噪声直接进 PID 微分项 periph_mpu60x0.c / control.c L141 / L205

问题描述: MPU6050 的 LPF 寄存器 (reg 26) 设为 0x00，即 256Hz 带宽——几乎没有低通滤波。DMP FIFO 中的陀螺仪数据直接被 imu_get_gyro(IMU_INSTANCE_MPU, 1) 返回，用于平衡 PD 控制器的微分项。高频噪声被 BALANCE_KD = 7.53 放大后直接出现在 PWM 输出中。

// periph_mpu60x0.c L141 — MPU 内部 LPF = 256Hz
mpu60x0ReliablySetReg(26, 0x00);

// control.c L205 — DMP 原始陀螺仪直接进 PID
_control.pitch_gyro = (float)imu_get_gyro(IMU_INSTANCE_MPU, 1);

// control.c L75-76 — Kd=7.53 放大噪声
return _control.balance_kp * (pitch - BALANCE_ANGLE)
     + _control.balance_kd * pitch_rate;  // 7.53 × 噪声
修复（二选一）

方案1: 在 mpu_dmp_init 中追加 MPU LPF 寄存器配置:

// 在 mpu_dmp_init 的 run_self_test() 之前添加
mpu60x0write(MPU60x0_ADDR, 26, 1, &(uint8_t){3});  // 42Hz LPF

方案2: 在控制层用项目已有的二阶 Butterworth 滤波器:

static struct SecondOrderLowPass_t _gyro_lpf;
// 初始化: init_second_order_low_pass(&_gyro_lpf, 40.0, 200, 0.707, 0.0);
// 使用: pitch_gyro = update_second_order_low_pass(&_gyro_lpf, raw_gyro);
中 IMU 模块约 400 行校准/滤波代码为死代码 imu.c L71-90, L163-257, L346-437

问题描述: imu_init() 中大部分代码被注释，mpu60x0_init() 也未启用传感器（config 被注释）。所有 imu_get_gyro/acc 函数直接返回 get_dmp_gyro/accel，绕过了本地校准和滤波管线（imu_calib_acc、imu_calib_gyro、2nd/4th 阶 Butterworth LPF）。

建议

策略A（精简）: 删除/归档死代码，只保留 DMP 接口封装。
策略B（增强）: 恢复本地校准+滤波管线，绕过 DMP 直接读寄存器，可提升数据质量但工作量大。

中 DCM AHRS 融合（~1900 行）完全旁路 txg_ahrs_fusion.c L1784-1798

问题描述: ahrs_update_fusion() 在 main.c 中被注释。get_roll_deg/pitch_deg/yaw_deg 直接返回 get_dmp_ahrs()。DMP 的偏航角(yaw)存在长时间漂移。对于平衡小车 pitch/roll 足够，但 yaw 精度有限。

建议

保留 DMP 用于 pitch/roll。对 yaw 通道增加互补滤波器融合陀螺积分和 DMP yaw 输出，纠正漂移。

4 控制算法层 — PID

高 速度积分缺少 dt 时间因子 control.c L88

问题描述: _speed_integral += speed_error 没有乘 dt。当前隐式假设固定 5ms 周期，但协作式调度器在 I2C 阻塞时周期会波动。缺少 dt 导致积分速率不稳定。

修复
// 在 Control_Updte 开头计算 dt
static uint32_t last_tick = 0;
float dt = (float)(HAL_GetTick() - last_tick) * 0.001f;
last_tick = HAL_GetTick();
if (dt <= 0.0f || dt > 0.05f) dt = 0.005f;

// 积分累加改为
_speed_integral += speed_error * dt;

// VEL_KI 定义改为以秒为单位: 原 140/200=0.7 → 新 140.0 (1/s)
#define VEL_KI  140.0f  // 单位: 1/s
中 NEW 积分抗饱和仅简单钳位 — 无条件积分 control.c L88-91, L234-237

问题描述: 速度积分仅用 clamp_float 限制在 ±8000，但在 PWM 输出已饱和（±6000）时积分仍在累加。当小车从倾斜恢复时，积累的积分项会导致超调。

修复 — 条件积分（仅在输出未饱和时积分）
// 先计算 balance + velocity 的和
float raw_output = balance_pwm + velocity_pwm;
bool saturated = (fabsf(raw_output) > LIMIT_PWM);

// 仅在未饱和或饱和方向与误差方向一致时停止积分
if (!saturated || (raw_output > 0) != (speed_error > 0)) {
  _speed_integral += speed_error * dt;
}
_speed_integral = clamp_float(_speed_integral, -LIMIT_SPD_INTEGRAL, LIMIT_SPD_INTEGRAL);
中 转向环 turn_kd 参数已接收但未使用 control.c L97-101, L162

问题描述: control_turn() 只有 P 项，turn_kd 始终为 0 且未参与计算。纯 P 控制的转向环在目标偏航速率突变时容易超调。

修复
static float prev_yaw_rate_error = 0.0f;

static float control_turn(float target_yaw_rate)
{
  float err = _control.yaw_gyro - target_yaw_rate;
  float d_err = (err - prev_yaw_rate_error) / 0.005f;
  prev_yaw_rate_error = err;
  return _control.turn_kp * err + _control.turn_kd * d_err;
}
中 速度滤波器仅一阶 IIR — 项目已有 Butterworth 未用 control.c L85

问题描述: SPEED_FILTER_ALPHA = 0.23 的一阶 IIR 在 200Hz 下截止约 7.3Hz，滚降仅 -20dB/dec。项目已有现成的二阶 Butterworth 实现（txg_low_pass_filter.c）未使用。

修复
static struct SecondOrderLowPass_t _speed_lpf;
// 初始化: init_second_order_low_pass(&_speed_lpf, 10.0, 200, 0.707, 0.0);
_control.encode_spd = (float)update_second_order_low_pass(
    &_speed_lpf, (double)measured_speed); // -40dB/dec
低 NEW float_to_i16 截断而非四舍五入 — 引入系统性偏差 control.c L38-42

问题描述: (int16_t)value 向零截断而非四舍五入。正值偏小、负值偏大（如 3.7→3, -3.7→-3），在高频 PWM 输出中引入约 0.5 LSB 的系统性直流偏置。

修复
static int16_t float_to_i16(float value)
{
  value = clamp_float(value, -32767.0f, 32767.0f);
  return (int16_t)(value + (value >= 0 ? 0.5f : -0.5f)); // 四舍五入
}

5 任务调度与通信层

中 协作式调度无优先级 + UART ISR 调试残留 + TIM2 ISR 全局关中断 main.c / bsp_uart_drv.c / bsp_timer_drv.c

15a. 调度器无优先级

sys_task_run() 按数组顺序执行，无优先级抢占。mpu_dmp_get_data 的 I2C 阻塞（2-5ms）会延迟后续 Control_Spd_Updte 和 Control_Updte。建议调整任务顺序：控制任务放最前，DMP 读取放后面且改为 10ms。

15b. UART ISR 调试残留变量

bsp_uart_drv.c 的 HAL_UARTEx_RxEventCallback 中有全局变量 revlength 和 x，每次接收都执行 revlength%52 运算。这些调试代码应删除。

// bsp_uart_drv.c L199-213 — 调试残留
uint64_t revlength = 0;  // 应删除
int x = 0;           // 应删除
// L210-213: if(revlength%52!=0){ x++; } ← 删除

15c. TIM2 ISR 全局关中断

bsp_timer_drv.c L344-348 中 TIM2 中断回调使用 __disable_irq()/__enable_irq() 关闭所有中断。虽然 TIM2 当前未启动（main.c L81 被注释），但如果启用会导致 UART 和编码器中断全部被阻塞。应改为仅关闭 TIM2 自身中断或使用 BASEPRI。

15d. UART 命名混乱

UART5_ID 实际对应的是 USART1（PA9/PA10），变量名 uart5_handle 实际是 USART1 handle。这容易引起维护混乱，建议重命名。

15e. Net_Link_Out 效率

注册为 2ms 任务但内部计数器每 5 次才发送（10ms），4/5 次空转。建议改为 10ms 任务。TA 遥测帧被注释，无法在线查看传感器数据。
