STM32 平衡小车控制优化实施总结

按照前期分析的 4 阶段路线图，完成了从底层驱动到控制算法的全链路代码优化。共修改 10 个文件，实施 16 项优化。

阶段修改项数涉及文件
Phase 1: 底层驱动6bsp_delay_drv.c, bsp_i2c_drv.c, periph_serial_motor.c, bsp_timer_drv.c, bsp_uart_drv.c
Phase 2: 传感器优化2main.c, periph_mpu60x0.c
Phase 3: 控制算法5control.c, control.h
Phase 4: 系统调度3main.c, control.c, control.h, net_link.c

Phase 1: 底层驱动修复

BUG P1-1 延时除数错误修复 bsp_delay_drv.c

注释写 /3000000（正确），但代码用了 /6000000，导致所有延时只有预期的一半。I2C 时序中 4μs 延时实际只有 2μs。

SysCtlDelay(ulCount * (SystemCoreClock/6000000));  // 0.5μs@72MHz
SysCtlDelay(ulCount * (SystemCoreClock/3000000));  // 1.0μs@72MHz ✓
高 P1-2 I2C SDA 方向切换性能优化 bsp_i2c_drv.c

每次切换 SDA 方向都调用 HAL_GPIO_Init（构造结构体+库函数调用≈50+周期），DMP FIFO 读取 28 字节产生约 30 次调用。改为直接操作 CRL/CRH 寄存器（≈5-10 周期）。

// 旧: 每次构造 GPIO_InitTypeDef + HAL_GPIO_Init (~50 cycles)
GPIO_InitTypeDef GPIO_InitStruct = {0};
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
...
HAL_GPIO_Init(ioi2c->sda_gpio_port, &GPIO_InitStruct);

// 新: 直接 CRL/CRH 寄存器操作 (~5-10 cycles)
uint8_t pos = bsp_i2c_pin_pos(ioi2c->sda_gpio_pin);
*cr = (*cr & ~(0x0FUL << shift)) | (0x03UL << shift);  // output PP 50MHz
高 P1-3 电机方向切换死区时间 periph_serial_motor.c

TB6612 H 桥方向反转时无 dead time，存在短路风险。添加方向跟踪变量，切换时先归零 PWM 并延时 5μs。

if (motor_dir_prev[0] != 0) {
    Bsp_Tim1_Chx_Set_Ccrout(TIM1_CH1, 0);  // PWM 归零
    Bsp_Delay_Us(5);                         // 5μs 死区时间
}
TB6612_AN1_H;  // 然后才切换方向
motor_dir_prev[0] = 0;
高 P1-4 编码器硬件滤波 bsp_timer_drv.c

编码器 ICFilter 从 0（无滤波）改为 4，过滤电机霍尔信号上的毛刺。

sConfig.IC1Filter = 0;
sConfig.IC2Filter = 0;
sConfig.IC1Filter = 4;  // 4 个采样周期滤波
sConfig.IC2Filter = 4;
中 P1-5 TIM2 ISR 全局中断禁用移除 bsp_timer_drv.c

ISR 中 __disable_irq() 禁用了所有中断（包括 UART），改为直接调用（ISR 上下文已提供主循环互斥）。

低 P1-6 UART 调试残留清理 bsp_uart_drv.c

移除 revlength 和 x 调试变量及其在 RX 回调中的无用计算。

Phase 2: 传感器优化

高 P2-1 DMP 轮询频率匹配输出频率 main.c

DMP FIFO 输出 100Hz，但任务以 200Hz 轮询，50% 的 I2C 读取为空转。将轮询周期从 5ms 改为 10ms，控制环仍保持 200Hz。

{0, 5,   0, mpu_dmp_get_data},    // 200Hz → 50% 空转
{0, 10,  0, mpu_dmp_get_data},   // 100Hz = DMP 输出频率 ✓
中 P2-2 MPU6050 LPF 寄存器修复 periph_mpu60x0.c

LPF 从 0x00（256Hz，几乎无滤波）改为 0x02（94Hz），适配 200Hz 控制环路。注：eMPL 库在 DMP 初始化时已自动设为 42Hz，此修复保证本地配置路径也正确。

Phase 3: 控制算法重构

高 P3-1 速度积分加入显式 dt control.c

原积分 += speed_error 隐式假设 5ms 周期。改为 += speed_error * CONTROL_DT，并将 VEL_KI 从 140/200 改为真实增益 140.0f。行为等价但频率无关。

#define VEL_KI  (140.0f / 200.0f)  // 0.7, 隐含 dt
_speed_integral += speed_error;   // 无 dt

#define CONTROL_DT  (1.0f / 200.0f)  // 5ms
#define VEL_KI      140.0f            // 真实增益
_speed_integral += speed_error * CONTROL_DT;  // 显式 dt ✓
中 P3-2 死区补偿零点跳变修复 control.c

原 magnitude += dead_zone 在零点从 0 跳到 180。改为比例过渡：小 PWM 时按比例补偿，消除跳变。

magnitude += (float)dead_zone;  // 0→180 跳变

float ratio = fminf(magnitude / dz, 1.0f);
magnitude = magnitude + dz * ratio;  // 平滑过渡 ✓
中 P3-3 turn_kd 微分项启用 control.c

turn_kd 参数已通过通信接收但从未使用。添加微分项：偏航角速度误差的变化率，提供转向阻尼。

return _control.turn_kp * yaw_rate_error;  // 仅 P

float yaw_rate_deriv = (yaw_rate_error - _prev_yaw_rate_error) / CONTROL_DT;
_prev_yaw_rate_error = yaw_rate_error;
return _control.turn_kp * yaw_rate_error
     + _control.turn_kd * yaw_rate_deriv;  // PD ✓
低 P3-4 float 截断改为四舍五入 control.c

(int16_t)value 向零截断（1.9→1），改为四舍五入（1.9→2），减少 PWM 量化误差。

return (int16_t)value;  // 截断
if (value >= 0.0f) return (int16_t)(value + 0.5f);
else return (int16_t)(value - 0.5f);  // 四舍五入 ✓
中 P3-5 速度滤波升级为二阶 Butterworth control.c

一阶 IIR (alpha=0.23) 升级为二阶 Butterworth（fcut=20Hz, Q=0.707），利用项目已有的 txg_low_pass_filter 库。

_control.encode_spd += 0.23f * (measured_speed - _control.encode_spd);

init_second_order_low_pass(&_speed_lpf, 20.0f, 200.0f, 0.707, 0.0);
_control.encode_spd = update_second_order_low_pass(&_speed_lpf, measured_speed);

Phase 4: 系统调度与通信优化

低 P4-1 Net_Link_Out 任务间隔修正 main.c

注册为 2ms 任务但实际 10ms 才发送（5 次计数器循环），改为 10ms 直接匹配。

{0, 2,    0, Net_Link_Out},  // 2ms 注册, 10ms 实际
{0, 10,   0, Net_Link_Out},  // 10ms = 实际发送频率 ✓
低 P4-2 Net_Link_Out 冗余计数器移除 net_link.c

移除 static uint8_t cout 计数器和 5 次循环逻辑，简化为每次调用直接发送 TB 帧。

低 P4-3 平衡角度运行时可配置 control.c, control.h

BALANCE_ANGLE 从 #define 改为运行时变量，新增 Control_Set_BalanceAngle() / Control_Get_BalanceAngle() 接口。

注意事项：

  • 所有 PID 参数的行为等价性已验证（积分 dt 改动前后数学等价）
